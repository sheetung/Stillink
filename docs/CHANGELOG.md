# Stillink — 版本更新记录

## 未发布

- 天气与音乐自动卡片互斥，启用并保存一项会关闭另一项，并同步网页开关；手动图片上传成功后关闭两项自动刷新，保留配置。
- 设备设置新增 GitHub Release 在线升级：联网检查版本、自动匹配芯片 OTA 包、显示下载进度、校验后重启。
- 恢复 ESP32-C3 构建和深睡唤醒支持；Release 工作流统一生成 S3、C3 两种芯片的完整包与 OTA 包。
- 在线烧录页可选择芯片对应固件，并拒绝与已连接设备芯片不匹配的烧录包。

## V1.2.2 · 2026-10-13

- 修复局域网访问时固件升级仍发往热点地址的问题；上传前识别 OTA 应用固件，避免误上传完整烧录包。
- Windows 音乐客户端增加托盘图标与右键「退出」，移除重复的停止脚本。
- GitHub Actions 自动构建 Windows 工具包，随固件版本附加到 Release；解压 ZIP 后运行 EXE，音乐说明提供下载入口。

## V1.2.1 · 2026-10-13

- 新增基于官方 esptool-js 的单页在线烧录工具，部署于 GitHub Pages，默认使用 Release 中的 Stillink S3 OTA 固件，并支持完整包与本地 BIN。
- 固件统一输出到 `firmware/`，命名为 `stillink-vX.Y.Z-esp32s3.bin`；推送版本 tag 后自动构建 GitHub Release。

- Windows 音乐广播工具支持双击无窗口后台运行，默认无需配置；提供停止入口，必要时通过 `config.yml` 调整参数。

- 保存额外服务地址后展示天气、音乐状态卡片；音乐未收到近期 Windows 广播时显示「等待音乐」，不再将 UDP 接收端启动误报为音乐可用。

- 音乐卡片改为大封面模式，保留歌名与歌手。
- 额外服务配置支持连接检测，分别显示天气与音乐服务状态，检测失败时不保存。
- 增加 mDNS 与 HTTP 服务发现，可使用 `http://stillink.local/` 访问设备。

- 内置控制页改为构建时 gzip 压缩，浏览器自动解压，减少固件与网页传输体积；HTML 页面热更新格式保持不变。
- 将共用服务器与 Windows 音乐工具统一归入 `extra-services/`。
- 共用服务器改名 `stillink-services`，天气获取与渲染拆为独立模块。
- 新增额外服务总部署说明，天气和音乐文档独立描述各自使用方法。

## [V1.2.0] 2026-10-12

- 天气与音乐共用服务地址，统一在「设备设置 → 额外服务支持」配置。
- 未配置服务时隐藏天气和音乐入口；功能页仅保留各自的使用说明。
- Windows 广播工具支持补发延迟加载的专辑封面。
- 重写 README，补充拍立得、便签、天气、音乐及设备设置截图与部署步骤。

## [V1.1.0] 2026-10-12

- 增加「音乐」网页入口：预览、服务地址、启用开关；Windows 仅 UDP 广播音乐信息和原始封面，服务器绘图，ESP 检查切歌并主动下载。
- 新增「拍立得 → 便签 → 天气」入口，天气页面直接配置启用、位置及刷新时间。
- 使用 Open-Meteo 城市搜索和天气预报；增加 uv 隔离的天气服务，服务器渲染中文四色卡片，设备定时下载二进制帧并校验 CRC，浏览器无需保持打开。
- 默认当地时间 08:00、12:00、18:00 更新，首次启用立即更新；失败后保留画面，5 分钟后重试。
- 服务地址、位置和计划保存到设备，中文字库仅在服务器使用，重启与 OTA 后保留；恢复出厂清除。
- 天气和手动上传共用帧缓冲锁，避免同时刷新屏幕；屏幕驱动命令保持原样。
- 清理上游文档、旧方案与截图，API 文档直接提供帧格式。

## [V1.0.0] 2026-10-12

### 新增
- Wi-Fi 配网：点击网络名称自动扫描，连接成功后保存凭据，重启自动重连。
- 局域网 HTTP API、跨域支持及调用文档，支持查询设置、上传四色帧和刷新屏幕。
- 电池电压校准设置，以及 Stillink / MoInk 项目链接。

### 修改
- 正式版本仅支持 ESP32-S3，默认接线、构建及刷机工具统一为 S3。
- 联网后关闭热点，空闲自动轻睡并保持 HTTP 可访问；配网期间保持运行。
- 未联网时按设置进入深睡，默认空闲时间为 3 分钟。
- 桌面端选图／裁剪框与预览框等高。
- 固件、控制页和刷机包版本统一为 V1.0.0，API 契约保持 2。

### 验证与注意事项
- ESP-IDF 6.1 S3 构建与页面测试通过。
- S3 实机已验证 HTTP 上传；联网空闲 185 秒后 HTTP 仍可访问，响应约 177 毫秒。
- 轻睡功耗未测量；USB 调试连接可能阻止实际轻睡。
- 屏幕 BUSY 驱动保持原实现；此前刷新异常确认为接线接触问题。
- 已使用同分区表的 S3 固件可通过应用 BIN OTA；首次烧录使用整包 BIN，写入地址 0x0。
